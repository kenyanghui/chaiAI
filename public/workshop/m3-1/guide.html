1第 1 节 · 安：云服务器安家

本节目标：在腾讯云轻量应用服务器上开出一台自己的机器，并用 SSH 从自己电脑登进去｜预计 40 分钟

动手前确认：腾讯云账号已登录；浏览器能打开 console.cloud.tencent.com/lighthouse。
开机：买一台轻量应用服务器
  • 浏览器打开 console.cloud.tencent.com/lighthouse → 点「新建」
  • 地域选离你近的（如广州/上海）；镜像选系统类 · Ubuntu 22.04（课程统一口径，排障最快）
  • 规格选入门档即可（具体价格以当期招募页为准）；付款后 1–2 分钟状态变「运行中」
  • 在实例详情页记下两样：你自己的服务器公网 IP、你自己的登录密码（在「重置密码」处先设一个）
已有多台服务器任挑一台 Ubuntu 的用，不用新买
想用其他系统可以，但排障时请对照 Ubuntu 口径自己换包名
检查点（看到才算做对）：实例列表里这台机器状态为「运行中」，公网 IP 抄在本页底部
没看到怎么办：提示「库存不足」：换个地域再点新建；实名认证没过的先过认证
连通：从自己电脑 SSH 登录
  • 打开 SSH 终端（Windows PowerShell / Mac 终端），输入：ssh root@你自己的服务器公网 IP
  • 第一次连会问 are you sure，输 yes 回车；再输你自己的服务器密码（输入时屏幕不显示，正常）
  • 看到 root@… 这样的提示符就是登进来了
  • 把这条 ssh 命令记进手机备忘录，课后还要天天用
WindowsPowerShell 自带 ssh；提示「不是内部或外部命令」就去「设置→应用→可选功能」装 OpenSSH 客户端
Mac终端直接输 ssh 命令即可
检查点（看到才算做对）：终端里出现 root 开头的提示符，pwd 回车显示 /root
没看到怎么办：连不上：回控制台看防火墙是否放行 22 端口（默认放行）；密码错就去「重置密码」重设后重启实例
守门：给服务器立两条安全规矩
  • apt update && apt upgrade -y 打一轮系统补丁（几分钟，等它跑完）
  • 规矩一：控制台防火墙只保留 22（SSH）和后面 dashboard 要用的端口，其余端口一律不开——不教开危险端口，也不自己乱开
  • 规矩二：服务器密码只记在自己手机备忘录或密码管理器里，不发群、不写进任何文档；输错三次被锁就回控制台重置
想加密登录课后可配 SSH 密钥登录并关密码登录，课上先用密码统一口径
检查点（看到才算做对）：apt upgrade 无报错结束；防火墙页里没看到多余的放行端口
没看到怎么办：补丁装到一半断网：重新 ssh 登录再跑一遍 apt update && apt upgrade -y，会自动续上

症状可能原因解法
实例一直「创建中」地域库存紧张等 2–3 分钟刷新；超过 10 分钟换地域新建一台，旧的单删掉退钱
ssh 连接超时本地网络或防火墙拦了 22 端口控制台点「远程登录」（网页版终端）先进去干活，课后再修本地 ssh；网页终端全程可用，不影响交付

2第 2 节 · 装：openclaw 落地 + 模型接上

本节目标：在服务器上装好 openclaw，把模型 API key 写进配置文件，让助理有脑子｜预计 50 分钟

动手前确认：已 SSH 登录服务器；手边有你自己的模型 API key。
装 openclaw（官方安装脚本）
  • SSH 终端里执行：curl -fsSL https://openclaw.ai/install.sh | bash
  • 脚本会自动准备 Node 运行时并装好 openclaw（几分钟）
  • 装完执行 openclaw --version，出版本号即装好
  • （已有 Node 24.16+/26.1+ 的同学也可用 npm install -g openclaw@latest --allow-scripts=openclaw）
npm 老版本npm 11.15 及更早请去掉 --allow-scripts=openclaw 这个参数再装
检查点（看到才算做对）：openclaw --version 能打出版本号
没看到怎么办：下载慢/超时：重跑一遍脚本；反复失败就换 npm 方式装，两条路终点一样
初始化：跑一遍 onboard 向导
  • 执行 openclaw onboard --install-daemon，跟着向导走完
  • 向导会验证模型连通、建好工作区、配好 Gateway
  • 向导过程中让你填 API key 时，粘贴你自己的 API key（粘贴时终端同样不回显，正常）
  • 完成后执行 openclaw gateway status，显示 running 即 Gateway 已起
想看网页控制台openclaw dashboard 打开 Control UI，网页里发条消息能回就是通了
检查点（看到才算做对）：openclaw gateway status 显示运行中
没看到怎么办：向导中途退出：直接重跑 openclaw onboard --install-daemon，向导可重复进
落配置：改 openclaw.json 前先备份
  • 配置文件在 ~/.openclaw/openclaw.json，模型 API key 就写在这里
  • 铁律：改之前先备份——cd ~/.openclaw && cp openclaw.json openclaw.json.bak-1108（日期后缀，改坏一条命令复原）
  • 用 nano openclaw.json 打开，找到模型配置段，把 key 值换成你自己的 API key，Ctrl+O 保存、Ctrl+X 退出
  • 改完把 openclaw.json 的权限收到 600：chmod 600 ~/.openclaw/openclaw.json（key 文件不给别人看）
不惯用 nanovi/vim 都行；或把文件 cat 出来在本地编辑器改完再整段粘贴回去
检查点（看到才算做对）：ls ~/.openclaw/ 里能看到 openclaw.json.bak-* 备份文件；ls -l openclaw.json 权限位显示 -rw-------
没看到怎么办：改坏打不开：cp openclaw.json.bak-1108 openclaw.json 一条命令回到改前状态

本节排障表（4 个常见卡点）

症状可能原因解法
install.sh 卡住不动服务器访问外网慢Ctrl+C 中断重跑一次；连着两次就改走 npm 安装路线
onboard 验证模型不通过API key 填错或没充值去厂商控制台核对 key 是否复制完整（前后别带空格）、账户是否有余额；改完重跑 onboard
改完 json 后 openclaw 起不来配置文件语法改坏（多/少逗号引号）cp 备份文件复原 → nano 重开 → 只改 key 那一行的值，不动标点；改一行存一次
openclaw command not found安装脚本没把命令链进当前终端退出 ssh 重登一次；还没有就执行 npm install -g openclaw@latest 重装一遍

3第 3 节 · 跑：数字助理上线冒烟

本节目标：agent 一问一答冒烟通过，并用 systemd 把 openclaw 挂成常驻服务｜预计 45 分钟

动手前确认：openclaw gateway status 运行中；openclaw.json 已备份且 key 生效。
冒烟：一句话问助理
  • SSH 终端执行：openclaw agent --agent main --message "回复两个字：正常"
  • 等几秒，返回「正常」两个字就是全链路打通：服务器→openclaw→模型→回话
  • 把这条返回截图发到课程群，这就是交付 ② 的第一张凭证
  • 多问一句业务话试试，比如让它用一句话总结今天的日期和天气句式，确认不是只会说正常
返回慢首次调用模型有冷启动，等 10–20 秒；第二次起就快了
检查点（看到才算做对）：终端返回「正常」两个字，截图已发群
没看到怎么办：返回报错：看错误里带不带 401/key 字样——带就是 key 问题回第 2 节修；带 billing 字样回第 4 节看排障表
常驻：用 systemd 守住它
  • openclaw 自带的 daemon 负责守进程；执行 systemctl status openclaw-gateway 看一眼状态（服务名以 onboard --install-daemon 装出的为准）
  • 想让它开机自启：systemctl enable openclaw-gateway
  • 重启服务器验证一次：控制台点重启 → 再 ssh 进来执行 systemctl status openclaw-gateway，active (running) 就是真的常驻
  • 日常三条命令记牢：systemctl status / restart / stop openclaw-gateway
服务名对不上systemctl list-units | grep -i claw 一查便知，用查出来的名字替换
检查点（看到才算做对）：重启服务器后 agent 冒烟那条命令还能返回「正常」
没看到怎么办：重启后 status 不在：systemctl enable + start 再做一遍；还不行检查 ~/.openclaw 权限是否 600 改过头连目录都锁了（目录保持默认，只锁 json 文件）
挂车：把网页控制台也通上
  • 服务器上执行 openclaw dashboard，记下它给的端口
  • 回腾讯云控制台 → 防火墙 → 添加规则放行这个端口（只放这一个，别的仍然不开）
  • 浏览器开 http://你自己的服务器公网 IP:端口，能打开 Control UI 即通
  • 安全提醒：这个页面等于你助理的驾驶舱，用完随手关页；课后想更稳可回防火墙把端口再关掉，纯 SSH 用也完全够课业
打不开页面九成是防火墙没放行该端口；放行后等 10 秒刷新
检查点（看到才算做对）：浏览器里 Control UI 打开，发条消息有回复
没看到怎么办：页面开了但发消息没反应：回 SSH 跑 openclaw gateway status 确认运行中；不行就 restart 一次再刷新页面

本节排障表（4 个常见卡点）

症状可能原因解法
agent 返回「正常」以外的报错链路里 key、模型名、网络三处任一断了报错含 401/unauthorized → key 错；含 model/not found → 模型名写错；含 timeout → 服务器出网慢，重试一次
systemctl status 显示 failed配置文件改坏或 key 无效导致起不来cp 备份复原 openclaw.json → systemctl restart openclaw-gateway → 再冒烟一次
重启服务器后助理失联服务没设 enable，开机不自启systemctl enable openclaw-gateway 设自启；再重启验证一遍 status
dashboard 端口放行了还是打不开浏览器缓存或端口填错换无痕窗口；核对 URL 里端口和 openclaw dashboard 报的完全一致

4第 4 节 · 阵地：cron 定时值守任务

本节目标：配一条每天早 8 点把提醒推到群的 cron 任务，把「跑起来」变成「天天在岗」｜预计 45 分钟

动手前确认：agent 冒烟已通过；systemd 常驻已验证；手边有群机器人的 webhook 地址。
看家底：openclaw cron 命令族
  • SSH 终端执行 openclaw cron list，列出当前所有定时任务（刚装好是空的）
  • 这一族还有 openclaw cron edit <id> 等命令，先混个脸熟
  • 想好你的值守内容：一句话提醒（如「早 8 点推今日待办提醒到群」）
  • 把群机器人 webhook 地址备好（企业微信群 → 群设置 → 群机器人 → 添加 → 复制 webhook）
没有企业微信先用任何能在服务器上触达你的通道（如邮件 webhook）代跑，课后换
检查点（看到才算做对）：openclaw cron list 能正常执行不报错；webhook 地址已到手
没看到怎么办：cron list 都报错：回第 3 节确认 gateway 运行中，cron 依赖它
建任务：每天早 8 点推送（显式设 model）
  • 用 cron 建任务时，务必显式指定模型：不设会走错默认模型，直接报 billing error——这是最真实的坑
  • 建好后 openclaw cron list 查到任务 id，再执行 openclaw cron edit <id> --model <你的模型名> 补设/核设
  • 任务内容让助理干一件事：生成一句今日提醒（天气+待办+一句加油），推到群机器人 webhook
  • 时区注意：服务器默认 UTC，早 8 点北京时间 = cron 里写 0 点（UTC 00:00），写反了会晚 8 小时推
拿不准时区date -R 看服务器时区；+0000 就是 UTC，按上面换算
检查点（看到才算做对）：cron list 里能看到这条任务，model 列不为空、不是默认占位
没看到怎么办：建完没触发：把触发时间改成 2 分钟后实测一次，通了再改回早 8 点；报 billing error 就先 edit --model 补设
验收：人工触发一次 + 交付三件合影
  • 人工触发一次任务（或等 2 分钟短周期实测），群里收到那条提醒即验收通过
  • 三张截图合影发群：①控制台实例运行中 ②agent 返回「正常」③群里收到 cron 推送——这就是本场交付 ①②③
  • 把提醒词调得像你：改任务里的 prompt，让它带你的口吻，助理才有你的样子
  • 课后想加任务：同法再建，每条都记得显式设 model
推送成了但内容生硬回到任务 prompt，多给一句角色设定，如「你是XX的助理，说话简短客气」
检查点（看到才算做对）：群里收到那条早间提醒；三张截图已发群
没看到怎么办：群里没收到：webhook 地址复制不全（重新复制）；服务器 curl 一下 webhook 地址测通不通，通则问题在任务侧，回 edit 核对 model 与时间

症状可能原因解法
cron 一跑就报 billing error任务没显式设 model，走了错误默认模型openclaw cron list 拿到 id → openclaw cron edit <id> --model <你的模型名> → 人工触发验证。这条是本节第一坑，建任务时就显式设最省事

续30 天巩固计划（自助版）

工作坊的成果 30 天不用就会忘。每周一小步，周末 5 分钟自查没掉队。

时间做什么怎么自查没掉队
第 1 周每天 ssh 登一次服务器跑 agent 冒烟；顺手把 prompt 调成你的口吻一周 7 天冒烟全「正常」，且至少改过一版 prompt
第 2 周把 cron 提醒内容做厚：加待办、加一句书摘；观察哪条真被用上每天的推送你自己会点开看，而不是划走
第 3 周加第二条 cron 任务（如周五下午推周报素材）；每条都显式设 model两条任务都在点，且一周内没出过 billing error
第 4 周做一次全面体检：备份 openclaw.json、核对防火墙端口、重启服务器验证常驻体检完三张截图（备份/端口/常驻）留档，数字助理满月在岗
